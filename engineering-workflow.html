The ticket lifecycle

Delegation

The main session orchestrates and holds the decisions; execution goes to subagents. A subagent starts cold — none of the conversation reaches it — and it cannot ask a question. So the brief carries six things.

FieldWhat it carries
OutcomeWhat is true when this is done — a result, not stepsmakes the work possible
SkillWhich skill to run, by name
InputsAbsolute paths, and the facts it cannot look up
DoneCheckable criteria, with the command that proves themmakes it safe
FenceWhat it must not touch
ReportThe specific facts to return

If you cannot write the brief, you do not understand the task well enough to delegate it.

The vault, and the loop that feeds itself

The project's docs/ folder is an Obsidian vault. Documents link each other with wikilinks, and those links are what make it a graph rather than a pile. Filenames carry the effort — checkout-flow — Spec.md, not spec.md — because the graph shows the note's name and nothing else.

Severity decides obligation

SeverityWhat it meansObligation
criticalData loss, a security breach, or a broken production pathAlways fixed
highIncorrect behaviour a user meets, or a broken guarantee the code claimsAlways fixed
mediumA real defect with bounded blast radius, or a standard breach that costs laterOnly if you say so
lowWorth fixing, cheap to leaveOnly if you say so

The boundary between high and medium is the one that carries weight — it is where a fix stops being optional. wrap-up will not merge with a critical or high finding unresolved, no matter how firmly the PR was approved.

A finding is a defect caught. A cause that repeats is a hole in the process — and the two are not the same thing.

So every finding records why it was not prevented, and the review record persists in the vault. This is the one part of the loop that cannot be reconstructed later: without a written cause, recurrence is invisible and the vault accumulates incidents instead of lessons. Causes name the gap — “the spec never said which seam” — not the moment or the person. “Missed it” is unmatchable and unfixable.

harden turns recurrence into a rule

  1. Group by cause, not symptomTwo findings that look unrelated can share one hole in the process. Clusters are weighted by severity — recurrence at critical earns an amendment sooner than recurrence at low.
  2. Find the ownerOne test: what single artifact, present when the defect was introduced, would have stopped it? A missing rule points at the axis; a loose completion criterion at the skill that let it pass as done; a permitted action at the agent definition.
  3. Sharpen, don't appendWhere an existing rule was almost right, it gets rewritten rather than joined by a second one nearby. A rule added per incident is sediment — and is how the original rule stayed weak enough to miss this.
  4. Propose, don't applyA skill change alters every future run, so nothing lands from a pattern you have not seen. Runs periodically, never per review — one occurrence is not a pattern.

It runs in the SoVai repo, where the skills live, reading vaults from whichever projects you point it at. A cause appearing once in each of three projects is invisible from inside any one of them — and that is the pattern most worth catching.

Debug

A bug gets no special path. It gets diagnosed, and the diagnosis produces a ticket that enters the same flow as everything else — implemented under TDD, reviewed, merged on your approval.

  1. EvidenceGet an instance of the bug, preferring to go and get it — the database, the browser, the logs — over accepting the report. A reported symptom is a secondhand account.
  2. Build the feedback loopOne command, already run once, that is red-capable, deterministic, fast and agent-runnable. Reaching for a hypothesis before that command exists is the exact failure the discipline prevents.
  3. Reproduce and minimiseCut until every remaining element is load-bearing — removing any one of them turns the loop green.
  4. HypothesiseThree to five, ranked, each falsifiable with a stated prediction. A hypothesis with no prediction is a vibe.
  5. Test them in parallelOne hypothesis per agent. They are independent by construction, and one agent testing several in sequence anchors on whichever it tried first.
  6. File the ticketEvidence, the reproduction command, the minimised repro, the root cause, the seam analysis, and what would have prevented the bug.
