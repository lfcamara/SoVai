# Completion is gated globally, by one always-on rule

One skill — `verify-before-claiming` — forbids any claim of done, fixed, passing, working, or complete that is not accompanied by the output of the check that proves it. It applies to every kind of work, in the orchestrator and in every subagent alike, rather than being distributed into the skills that happen to produce completion claims.

The reasoning is coverage, not emphasis. A rule that lives inside a skill only fires when that skill is invoked, so it is silent for exactly the runs where nothing was invoked — a quick fix, an ad-hoc edit, a question that turned into a change. Those are also the runs where an unverified "done" is most likely, because no process was running to produce evidence in the first place. A gate whose reach depends on which skill fired is a gate with a hole shaped like every session that skipped the skill.

Relying on each skill's own Done criteria was the status quo and was rejected for that reason. It is not merely weaker in aggregate; it fails asymmetrically, covering the disciplined path and leaving the undisciplined one open. It also duplicates one meaning across many skills, so sharpening the standard becomes an edit in every file that states it, which `writing-great-skills` names as the cost of losing a single source of truth. The per-skill criteria stay where they are — they say *what* to check for that kind of work, which is genuinely local — and this skill says that whatever the check is, its output travels with the claim.

A hook was the other candidate and was rejected on mechanism rather than on principle. The plugin's hook layer enforces what a hook can observe — that an edit happened, that a skill was entered, that a session is ending — and it earns its place doing exactly that. What it cannot observe is whether the sentence about to be written to the user carries evidence. The failure this gate addresses is not an unrun command; it is a run that happened and a report asserting more than the run supports, or a report with no run behind it at all. That lives in the text of the claim, which is the model's output and not a hook's input. So this one has to be a rule the model is holding while it writes, and the two layers divide cleanly: the hook gates the act, the skill gates the account of it.

The one place the rule bends is the subagent boundary, and it bends without weakening. ADR-0007 keeps lint, build and test output inside the subagent because that output is enormous. So what crosses the boundary is the command, its result, and the failing lines — a compressed form of the evidence, never a verdict with nothing behind it.
